# OOMP Stage 1 completion report

Stage 1 is implemented and acceptance checks passed on 2026-10-13 (Asia/Karachi). Work stops here. Stages 2–10 remain planned.

1. **Workspace and repository.** `D:\Desktop\OOMP`. The directory was empty and had no ancestor Git repository, so it was independent of TRACE. A local `.git` was initialized. No TRACE files or checkout were accessed or modified.

2. **Project files created.** `.gitignore`, `LICENSE`, `README.md`, `pyproject.toml`; nine package files under `src/oomp` (root `__init__.py`, `__main__.py`, `cli.py`; domain `__init__.py`, `enums.py`, `models.py`, `interfaces.py`; retrieval `__init__.py`, `contracts.py`); `tests/test_stage1.py`; and seven documentation files: `architecture.md`, `memory-model.md`, `security-model.md`, `research-plan.md`, `roadmap.md`, `validation.md`, `stage-1-report.md`. Generated `.venv`, caches, build metadata and verification artifacts are local and Git-ignored. No sample.env is needed because Stage 1 has no configuration.

3. **Package architecture.** Distribution `oomp-memory` version `0.1.0`, import package `oomp`, Python `src` layout, setuptools packaging, argparse CLI. Domain code owns validated evidence/identity/scope/time values. Retrieval code defines inputs/evidence/paths/outputs. Protocols invert dependencies without storage/provider implementations. Package naming does not assert a reserved PyPI name or publishing ownership.

4. **Domain models.** Frozen Pydantic v2 `MemoryEvent`, `SourceReference`, `MemoryNode`, `MemoryEdge`, `RequestedScope`, `AuthorizedScope`. Unknown fields are rejected. Event/source combinations distinguish user assertions from generated assistant content. Nonblank content, bounded identifiers, evidence lists and confidence are validated. Nested metadata is an immutable detached JSON snapshot.

5. **Enums.** EventType: user_message, assistant_message, document, tool_result, correction, feedback. SourceType: user, assistant, document, tool, system. MemoryType: episodic, semantic, profile, procedural, project_state, resource, decision, topic_summary. MemoryStatus: active, superseded, retracted. RelationshipType: ABOUT, RELATED_TO, PART_OF, DERIVED_FROM, OCCURRED_IN, SUPPORTS, CONTRADICTS, SUPERSEDES, DEPENDS_ON. There is no universal graph acyclicity requirement.

6. **Temporal validation.** Naive timestamps are rejected; aware timestamps normalize to UTC and JSON uses ISO 8601 `Z`. Nodes require updated_at >= created_at. Node/edge/evidence validity requires valid_until >= valid_from when both exist. Validity is half-open; null bounds mean unknown rather than permanent truth. Occurrence, ingestion, source and record times remain separate and explicitly supplied.

7. **Provenance.** Events require a structured source reference. Nodes require nonempty source_event_ids and provenance references. Edges require nonempty source_event_ids; retrieval evidence requires nonempty source references. References carry source system, external event/document ID, timestamp and optional session/turn/locator. Confidence defaults to null and is finite in [0,1] only when supplied; it is never generated by these schemas.

8. **Scope design.** Tenant and namespace are distinct from principal. RequestedScope describes untrusted client intent; AuthorizedScope adds a required principal_id supplied by trusted service code after policy/authentication. Construction alone is not authorization. Persistent store and extraction/retrieval protocol operations require explicit authorized scope. Cross-record tenant linkage and authorization enforcement are future service/storage responsibilities.

9. **Retrieval contracts.** RetrievalRequest validates scope/query, strict max_results 1–100 (default 8), token_budget 1–32768 (default 1200), and optional aware as_of. MemoryEvidence includes canonical text/type, sources, optional measured score, status/validity, graph paths and metadata. GraphPath validates adjacent edge/relationship counts. RetrievalResponse contains retrieval_id, evidence/reference/path lists and a nonnegative estimated token count; an empty response is valid. No retrieval engine, fake scores or generated answer is provided.

10. **Interfaces.** EventStore append/get; MemoryStore put/get; GraphStore put_edge/edges_for; EmbeddingProvider embed; MemoryExtractor extract; MemoryRetriever retrieve. These are minimal synchronous Python protocols, with no database or provider-specific dependency.

11. **CLI.** `oomp --help`, `oomp --version`, `oomp doctor`, and `python -m oomp` work. Doctor validates Python compatibility, installed distribution/Pydantic versions and required imports, with nonzero exit on failed checks. It reports only Stage 1 package readiness.

12. **Dependencies.** Required Python >=3.11 and Pydantic >=2.9,<3; development pytest >=8,<10; build setuptools >=77. Actual local versions: Python 3.11.4, Pydantic 2.14.1, pytest 9.1.1, setuptools 84.0.0, wheel 0.48.0 and oomp-memory 0.1.0. Pip installed normal transitive dependencies in `.venv`; global packages were unchanged. SQLite persistence, embedding/vector libraries, MCP v2 and optional extraction providers are planned separately and were not installed.

13. **Installation procedure.** From OOMP: `py -3.11 -m venv .venv`, optionally activate, then `.\.venv\Scripts\python.exe -m pip install -e ".[dev]"`. Direct environment executables work when activation or the bare Python launcher does not. README includes both Windows procedures. Initial dependency installation may need network; runtime CLI/tests do not.

18. **Security assumptions.** Local CLI has no listener and sends no memory to providers. Retrieved/stored text remains untrusted. Assistant assertions are not verified user truth. Future services must authenticate principals, map authorized scope, enforce linkage/index isolation, govern privileged writes and implement deletion throughout derived data, indexes and backups. These are design contracts, not operational security services.

19. **Future decisions.** Confirm durable ID/idempotency behavior, canonical-key uniqueness, roles/grants, evidence spans/extraction version metadata, relation-specific endpoint policy, erasure/tombstone retention, configurable budgets/limits, tokenizer accounting, embedding versions, sync/async adapters and MCP transport/security compatibility when those stages begin.

Scope models do not authenticate; schemas do not verify record existence, truth, cross-tenant links or token-budget compliance. Full execution was validated on Windows/Python 3.11.4 with the installed dependencies, not every supported Python/version combination.

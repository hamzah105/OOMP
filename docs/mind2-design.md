# Mind 2 acquisition design (P2)

This decision precedes P2 source edits. P1's local stabilization gate has passed.

Keep the Stage 3 deterministic extractor, synchronous extraction CLI and manual
Mind default compatible. Add a versioned acquisition package. New product
profiles explicitly select its rules mode; existing profiles retain their
identity and legacy mode until an operator changes configuration. Embedding and
extraction settings are separate. No host or TRACE changes are needed.

Providers propose bounded typed records with exact spans. The independent
validator derives authority from the trusted scope and stored event, classifies
the source conservatively, and permits only source-extractive objects. Model
prose, confidence and instructions cannot establish truth or operational power.
Unrecognized, uncertain, quoted and assistant material can be retained only as
attributed episodes or review items, never as asserted user-profile truths.
Secrets/injection and excluded sensitivity are filtered before inference.

Preserve old canonical IDs for supported legacy statements. New durable claims
receive versioned stable keys; every accepted clause also has an event-specific
episodic record, with exact quote, timestamp, role, assertion and promotion
decision. Low-salience events remain episodic. Corrections are reviewable
additions and do not rewrite history, identities or source permissions.

**No schema migration is necessary.** Use existing `memories`, `memory_sources`,
`topics`, `topic_memberships`, `mind_summary_revisions` and
`mind_summary_sources`. Bounded session/time/topic projections group episodic
records. Compact chronological extractive revisions use the existing summary
contract and evidence tables, with a new versioned formatting policy. Full P3
hierarchies and P4 retrieval/ranking remain deferred. Ordinary retrieval still
uses the established memory/index APIs; local episode inspection is explicit.

Model calls occur only in configured background Mind jobs, outside SQLite
transactions. Rules run even when the local model fails. Bound HTTP time,
request/response bytes, output tokens, candidates, concurrency and repeated
failures. Disable proxies and redirects; accept only explicit literal-loopback
HTTP endpoints. No downloads, service startup or external-provider calls.
A provider protocol supplies the seam for separately authorized future APIs.

Commit revalidates source existence, exact content, scope, retractions and job
owner/fence/lease in one write transaction before derived writes and again
before commit. Episode reads and summaries check live evidence; source erasure
continues through existing dependency planning. Reprocessing requires an
explicit bounded event-ID selection, consent assertion, preview and matching
plan digest; it enqueues jobs rather than crawling history.

Validation: old and new Python 3.11/3.12 suites, real native ACL regressions,
malicious providers, expiry/cancellation/erasure during inference, idempotence,
episode chronology/attribution/retraction, no-model degradation, private profile
compatibility, package installation and synthetic lifecycle checks. Freeze at
least 30 multi-turn synthetic sessions and 200 annotated opportunities before
evaluation. Labels are Codex drafts pending independent human review. Compare
legacy, improved rules and actual installed local-model runs on identical
inputs and denominators. Preserve raw misses, timings and resource limits.
